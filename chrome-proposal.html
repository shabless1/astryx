The trap inside option A

I tested A against all forty day-states before drawing any of this. The corrective palette only cools when a signal is elevated. When it is depleted the palette deliberately warms — that is correct therapy inside a mandala, and it is the old complaint all over again at full-viewport scale. Six states resolve to a red-band hue on the naive read. Mars balanced is Warm Red. Pluto depleted is Deep Burgundy.

So A only works with a guard: chrome takes the first member of the state's corrective palette that is not in the red band, then is tempered to a chrome envelope. Every cell below is what ships. The six marked ✕ are the ones the guard caught.

What each one costs

Recommended

A · The room calibrates

Chrome takes the enveloped corrective colour for the carrier's current state. Mars running hot and the room goes blue-green. Never-amplify, applied to colour — the law that already governs fork selection.

The cost: the app's colour is no longer one fixed thing. It is a band of tempered hues, and the brand has to be carried by the bone strips, the type and the near-black ground instead.
Safest

B · One fixed room

Chrome stays antique gold for everyone, every day. The corrective palette lives only in the chamber, where it already works. This is what is live right now.

The cost: it stops the harm and throws away the medicine. A room that is the same for everyone is a theme, not a calibration.
Middle

C · Warms and cools only

One neutral family, temperature-shifted by state. Hot days cool the room, depleted days warm it. The planet's identity never reaches the chrome at all.

The cost: four rooms total. It reads as a mood setting rather than a reading, and a Mars day and a Neptune day in the same state look identical.

The rule, either way

for the house-style skill

Whichever model you pick, two lines get written into the house style and enforced in code, because the failure was never a hue — it was that nothing stopped one.

  1. No chrome element may take a planet's base palette. Base is identity; chrome is the room.
  2. No chrome element may render a hue listed in that planet-state's avoid. The engine names what must not be shown; the presentation layer has to read it.

Under B and C those rules hold by construction. Under A they need the envelope guard above, and a test that walks all forty states on every build so it can never quietly come back.

Palettes read directly from src/lib/visual/planetColorTherapyLibrary.ts — nothing here is invented. The persistence trap is already fixed and live: accentColor is out of the persist whitelist, and a migration releases every browser that was pinned to an old hue.
