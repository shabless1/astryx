## 0. READ ME FIRST — Compliance guardrails (non-negotiable for all marketing)

ASTRYX is a **wellness / observational-reference** product, not a medical one. This constrains **every word** marketing publishes, in or about the app.

- **Never make medical claims.** No "treats," "cures," "heals," "diagnoses," "prescribes," "clinically proven," "FDA-approved," "guaranteed," "permanently." These are code-banned inside the app and must not appear in marketing either.
- **Use probabilistic framing:** "may support," "may correlate with," "is traditionally associated with," "designed to help you recalibrate." Positioning line: **"Calibration, not prediction. A blueprint, not a reading. Signal, not sign. System, not mysticism."**
- **Voice register:** energy / frequency / vibration / the senses / medical-astrology. **NOT** occult / ritual / mystical / grimoire language. (Sha is personally spiritual; the *product* is deliberately not.) The one sanctioned metaphysical term is the **auric / etheric field** (the app's 6th sense — see §3).
- **Always pair with the disclaimer** where claims live: *"ⓘ Reference tool · Not medical advice."* It renders on every screen in-app; mirror it in ads/landing pages that describe effects.
- **Astryx (the AI) is a guide, not a professional or a person** — label AI-generated content as such.
- The full constitution lives in the repo at `COMPLIANCE.md`. Read it before writing claim-adjacent copy.

## 2. CORE LOOP

**First-time (onboarding), ~5 minutes:**
1. Land on **myastryx.com** → **Sign Up** (Google or email/password). *The app is account-only — no anonymous use.* Fork buyers must use their **checkout email** to auto-unlock access.
2. Accept a one-time consent screen ("Before you begin" — 18+, reference-tool acknowledgment).
3. **Birth Blueprint** (4 steps): name, birth date, birth time (or "I don't know" → Solar Chart mode), birth city; choose body map; run the **resonance scan** (tap what feels true across 10 planetary systems); rate energy 1–10; a few words in your own language; an intention. → **Generate my protocol**.
4. See **Today's Reading**: your carrier planet, why the signal is present, and your fork sequence.
5. Enter the **Resonance Chamber**, press play → a guided, timed session of tones + breath. Strike your fork on "Strike now," hold, release. Tap **Complete Session** and rate how you feel.

**Daily returning loop (the retention engine), ~seconds to start:**
1. Open → **Daily Check-In** dashboard (chart is never re-asked).
2. **Today's Pulse** tab shows today's **Temperature** (Cool/Warm/Hot), a headline (readable aloud), live transits vs your chart, and a **Suggested Fork**.
3. Tap a **session tile** — Today's Calibration, Full Body, or Chakra — straight into the Chamber.
4. Run the session with your forks → complete → energy trend logs to History.
5. Ask **Astryx** (the in-app AI guide) anything about the reading; she can also set up the next session for you.

**Value moment:** the felt shift after a guided fork-and-breath session, plus the "this is *specifically* mine and it's the same every time" trust of a deterministic system.

## 7. INTEGRATION SURFACE (read this closely — it governs "publish content into it")

**There is NO public/partner API and NO content-management API today.** The app's HTTP endpoints are **first-party, session-gated** (NextAuth JWT) or **secret-signed** — they are not designed for a third party (or a marketing AI) to call directly. There is currently **no programmatic "publish a post/article/reading into the app" endpoint.**

**Existing endpoints (all under `https://myastryx.com/api/…`, first-party):**
| Endpoint | Purpose | Auth |
|---|---|---|
| `/api/auth/[...nextauth]` | Sign in / session | NextAuth |
| `/api/chart` | Natal/solar chart calc | session |
| `/api/geocode` | City → coords/timezone | session |
| `/api/intake/interpret`, `/api/protocol` | Narrative themes / protocol gen | session |
| `/api/readings`, `/api/readings/latest` | Persist / fetch a user's reading | session (per-user) |
| `/api/sessions` | Log a chamber session | session |
| `/api/astryx`, `/api/teach` | Ask-Astryx AI | session + server-side OpenAI key |
| `/api/speak` | TTS voice | session + server-side OpenAI key |
| `/api/catalog` | Music catalog manifest (R2) | public read |
| `/api/payment/xrp` | XRP payment verify | session |
| `/api/webhooks/shopify` | **Fork-buyer entitlement** (orders/paid) | **HMAC** (`SHOPIFY_WEBHOOK_SECRET`) |

**How to actually read/write data today (for ops):**
- **Read (analytics, user/entitlement/session data):** query the **Supabase Postgres** directly with DB credentials (SQL). This is how the current daily analyst routine works. This is the reliable programmatic read path.
- **Grant access programmatically:** insert an `Entitlement` row (idempotent by `shopifyOrderId`) or add an email to the `BETA_ALLOWLIST` env var. The Shopify `orders/paid` webhook already does this automatically for fork purchases.
- **Publish audio content into the app (the real "content" surface):** upload track files to the **Cloudflare R2** bucket and update the catalog manifest that `/api/catalog` serves — **the catalog must mirror the bucket**. This is a file-upload + manifest-commit + deploy flow, **not an API call**.
- **Publish knowledge into Astryx (the AI):** edit `src/data/appKnowledge.json` and run `npm run build:canon` (regenerates the retrieval index), then deploy. Again a repo/data flow, not an API.

**What it would take to give the Chief-of-Staff a real content/publish API `[PLANNED]`:**
1. A small **admin API** (e.g. `/api/admin/*`) protected by an **API key or admin-role OAuth** for: creating "editorial" content (posts/transit notes/announcements), and registering audio tracks.
2. A **content table/CMS layer** (there's no `Post`/`Article`/`Announcement` model today — the app has no editorial content surface at all yet).
3. An in-app place to *show* that content (e.g. a "What's New" / daily-note feed). Today the only user-facing "content" is the deterministic reading, the transit copy (data files), and the Music Library.
**Estimate:** a focused build — new DB model + admin-authed CRUD endpoints + one in-app feed surface. Ask the dev (Claude) to scope it when marketing is ready.
